# 0002 — 정밀도를 재현율보다 우선한다

- 상태: 확정
- 날짜: 2026-08-19
- 관련: [0004](0004-golden-set-first.md)

## 맥락

맞춤법 검사기의 품질 지표는 두 개다.

- **재현율(recall)** — 틀린 걸 얼마나 많이 잡는가
- **정밀도(precision)** — 잡은 것 중 진짜 틀린 게 얼마나 되는가

둘은 맞바꿈 관계다. 규칙을 넓히면 재현율이 오르고 정밀도가 떨어진다.

한국어에서 이 맞바꿈이 특히 가파른 이유가 있다. **같은 글자가 품사에 따라 띄어쓰기가 반대다.**

```
할 만큼 했다   ← 의존명사 (띄어 씀)
너만큼 했다    ← 조사     (붙여 씀)
```

문자열만 보면 구별할 수 없다. 앞말이 용언인지 체언인지를 알아야 한다.

## 결정

**정밀도 0.98을 합격선으로 두고, 재현율에는 합격선을 두지 않는다.**
문맥 없이 판정이 불가능한 갈래는 1층에서 **의도적으로 포기**하고 형태소 분석 층으로 미룬다.

## 근거

두 종류의 실패는 비용이 전혀 다르다.

| | 사용자가 겪는 일 | 회복 가능성 |
| --- | --- | --- |
| 못 잡음(FN) | 아무 일도 안 일어난다 | 규칙을 추가하면 회복된다 |
| 잘못 잡음(FP) | **맞게 쓴 글에 빨간 밑줄이 그어진다** | 확장을 지운다. 회복 불가 |

교정기는 사용자가 자기 판단보다 도구를 믿을 때만 쓸모가 있다.
한 번이라도 "얘 틀렸네"가 나오면 그다음부터는 모든 밑줄을 의심하게 되고, 도구는 소음이 된다.

또한 이 제품은 **리텐션이 목표**다. 한 번 쓰고 마는 도구가 아니라 매일 켜 두는 도구를 만들려면
"조용하지만 틀리지 않는" 쪽이 "많이 잡지만 가끔 틀리는" 쪽보다 낫다.

## 실제 적용

`packages/core/src/rules/spacing.ts`가 이 정책의 구현체다. 문자열만으로 앞말이 용언임이 **확정되는 자리**로만 규칙을 좁혔다.

- `-았/었/했/였 + 을` 뒤 → 앞말은 반드시 용언 (`했을 뿐`, `했을 리가`)
- `-는 / -던` 뒤 → 명사가 이 음절로 끝나는 일이 사실상 없다 (`아는 대로`, `하는 만큼`)
- 뒤따르는 말로 재확인 → `수`는 뒤에 `있/없`, `줄`은 `알/모르`

그리고 **다음 갈래는 1층에서 포기했다.**

| 포기한 것 | 이유 |
| --- | --- |
| `-ㄴ 지`(시간 경과) | 어미 `-ㄴ지`와 문자열이 완전히 같다. `범인인지 한 달` vs `먹은 지 한 달` |
| `-ㄹ 데`(장소·경우) | 연결어미 `-는데`와 겹친다. `밥을 먹는데` |
| `-을 만큼` | ㄹ받침 체언과 겹친다. `하늘만큼 땅만큼` |
| `안되다 / 안 되다` | 둘 다 표준어이고 뜻이 다르다 |
| `한번 / 한 번` | 부사냐 횟수냐에 따라 갈린다 |

각 규칙은 `counterExamples`(건드리면 안 되는 정상 문장)를 함께 들고 다니고, 이는 테스트로 강제된다.

## 결과

- 재현율은 낮게 시작한다. 의도한 것이다.
- 규칙을 추가할 때마다 "이게 오탐을 만들 수 있는가"를 먼저 묻게 된다.
- 형태소 분석 층(Phase 1)이 붙으면 포기했던 갈래가 열린다. 그때 재현율을 올린다.
