# 0006 — 점수 기반 오타 탐지(2층)를 시도했고 기각했다

- 상태: **기각**
- 날짜: 2026-08-19
- 관련: [0003](0003-three-layers-and-repo-split.md), [0002](0002-precision-first.md)
- 재현: `npm run build && node tools/experiments/typo-gain.mjs`

## 하려던 것

[ADR 0003](0003-three-layers-and-repo-split.md)에서 판정을 3층으로 나누며 2층을 이렇게 잡았다.

> **2층 · 형태소 이상 탐지** — 사전에 없는 표기는 억지로 잘게 쪼개진다.
>
> ```
> "어의없다" →  어/NNG + 의/JKG + 없/VA + 다/EF   ← 4조각
> "어이없다" →  어이없/VA + 다/EF                  ← 2조각
> ```

이게 되면 1층 사전의 한계를 넘을 수 있다. 사전은 우리가 적어 넣은 표기만 알지만,
2층은 **적어 넣지 않은 오타까지** 잡는다. 잡음 채널 모형으로 설계했다.

1. 어절의 분석 비용이 높으면 수상하다고 본다
2. 한국인이 실제로 혼동하는 **자모 한 개**만 바꾼 후보를 만든다 (임의 편집 거리는 후보가 폭발한다)
3. 후보의 비용이 눈에 띄게 낮아지면 그게 원래 쓰려던 말이다

구현해서 골든 테스트셋에 돌렸다. **정밀도 1.000 → 0.892, 오탐 14건.**

## 왜 안 되는가

오탐이 난 자리를 보고 임계값을 조정하는 대신, 이득(gain)의 분포를 직접 쟀다.

| 오타 (잡아야 함) | 최선 후보 | 이득 |
| --- | --- | --- |
| 괸찮아 | 괜찮아 | **+20.4** |
| 어의없다 | 어이없다 | **+18.0** |
| 찌게 | 지게 ← 엉뚱한 후보 | +13.7 |
| 폭팔 | 폭발 | +11.6 |
| 어떻해 | 어떠해 ← 엉뚱한 후보 | +10.4 |
| 희안하다 | 흿안하다 ← 엉뚱한 후보 | +0.9 |
| 설겆이 | 설겆의 ← 엉뚱한 후보 | +0.3 |
| 뇌졸증 | 놰졸증 ← 엉뚱한 후보 | 0.0 |
| 역활을 | — | **−3.3** |
| 오랫만에 | — | **−3.5** |

| 정상 (건드리면 안 됨) | 최선 후보 | 이득 |
| --- | --- | --- |
| 안으면 | 안의면 | **+16.5** |
| 포르르 | 푸르르 | **+16.0** |
| 메고 | 메구 | **+15.1** |
| 쌀은 | 살은 | +13.4 |
| 도와주셔서 | 도와주셯서 | +12.5 |
| 물이 | 물의 | +8.6 |

**두 분포가 겹친다.** 정상 단어 `안으면`(+16.5)이 진짜 오타 `설겆이`(+0.3)·`뇌졸증`(0.0)보다
훨씬 큰 이득을 낸다. 임계값을 어디에 두어도 한쪽을 버려야 한다.

원인은 둘이다.

1. **점수가 언어 모형 확률이 아니다.** garu-ko의 score는 격자 경로 비용이고,
   모르는 말은 통째로 `NNG`로 떨어뜨리는 대체 경로를 탄다. 그래서 `뇌졸증`도 `뇌졸중`만큼
   "그럴듯해" 보인다 — 애초에 둘 다 모르는 말이기 때문이다.
2. **엉뚱한 후보가 자주 이긴다.** `희안하다`의 최선 후보가 `흿안하다`이고,
   `도와주셔서`의 최선 후보가 `도와주셯서`다. 존재하지도 않는 표기가 점수를 얻는다는 것은
   이 신호가 "말이 되는가"를 재고 있지 않다는 뜻이다.

## 결정

**2층을 이 방식으로는 만들지 않는다.** `morph-typo` 규칙을 지웠다.

[정밀도 우선 정책](0002-precision-first.md)에 비추면 선택지가 없다.
재현율은 0.879에서 그대로였고 정밀도만 0.892로 떨어졌다 — **이득이 0인 채로 신뢰만 잃는 변경**이었다.

## 남긴 것

- `tools/experiments/typo-gain.mjs` — 위 표를 다시 만들어 내는 스크립트.
  "해 봤는데 안 되더라"는 주장 대신 **다시 잴 수 있는 측정**을 남긴다.
- `Analyzer.score?()` 인터페이스는 남겨 둔다. 다른 신호를 시도할 때 다시 쓸 수 있고,
  구현하지 않아도 되는 선택적 메서드라 짐이 되지 않는다.

## 다음에 시도할 수 있는 것

- **빈도 사전** — 표준 표기의 빈도 목록이 있으면 "후보가 사전에 있고 원본은 없다"로 판정할 수 있다.
  점수 대신 사전 유무를 보는 것이라 이번 실패의 원인 두 가지를 모두 피한다. 다만 사전을 구해야 하고,
  그 크기가 번들 예산([ADR 0001](0001-garu-ko-and-bundle-budget.md))에 맞아야 한다.
- **N-best 분석** — garu-ko의 `topN`이 완성되면 "1위와 2위의 차이"라는 더 나은 신호를 쓸 수 있다.
  현재 타입 선언에 *not yet fully supported*라고 적혀 있다.
- 그때까지 2층 자리는 비워 둔다. **없는 층을 있는 척하지 않는다.**
