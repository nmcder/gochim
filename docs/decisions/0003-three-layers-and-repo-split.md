# 0003 — 판정은 3층으로 쌓고, 저장소는 둘로 나눈다

- 상태: 확정
- 날짜: 2026-08-19
- 관련: [0001](0001-garu-ko-and-bundle-budget.md)

## 맥락 1 — garu-ko는 맞춤법 검사기가 아니다

형태소 분석기를 붙였다고 교정기가 되지 않는다. 실제로 돌려 본 결과가 그 사실을 그대로 보여 준다.

```
"그러면 않되요"  →  그렇/VA + 으면/EC + 않/VX + 되/EC + 요/JX
"그러면 안 돼요" →  그러면/MAJ + 안/MAG + 되/VV + 어요/EF
```

분석기는 문장을 형태소로 쪼갤 뿐, **"이건 틀렸다"고 말해 주지 않는다.**
심지어 이런 경우도 있다.

```
"됬어" →  되/VV + 었/EP + 어/EF
"됐어" →  되/VV + 었/EP + 어/EF      ← 완전히 동일
```

분석기가 `됬어`를 알아서 정규화해 버려서 **형태소만 봐서는 영영 못 잡는다.**

## 결정 1 — 판정 로직을 3층으로 쌓는다

| 층 | 방식 | 잡는 것 | 상태 |
| --- | --- | --- | --- |
| 1층 · 규칙 사전 | 문자열 패턴 + 받침 계산 | `됬/됐`, `않되/안 되`, `어의/어이`, 확정 가능한 띄어쓰기 | **Phase 0 완료** |
| 3층 · 품사 기반 띄어쓰기 | POS 태그 규칙 | 의존명사 vs 조사 판별 | **Phase 1 완료** |
| 2층 · 형태소 이상 탐지 | garu-ko 결과 분석 | 비정상적으로 잘게 쪼개진 구간 | 다음 |

### 3층을 붙이고 나서 (2026-08-19)

품사를 알자 1층이 예외 목록으로 겨우 막던 것들이 **저절로** 걸러졌다.

| 문장 | 1층이 필요로 하던 것 | 3층이 보는 것 |
| --- | --- | --- |
| 실수 없이 | ㄹ받침 명사 예외 목록 | `실수/NNG` — 한 덩어리 |
| 날것으로 | 한 단어 목록 | `날것/NNG` |
| 일리가 있다 | 한자어 예외 목록 | `일리/NNG` |
| 부재중 전화 | 화이트리스트 | `부재중/NNG` |
| 그 밖에 / 나 밖에 | 부정어 호응 가드 | `밖/NNG+에/JKB` vs `밖에/JX` |

그리고 1층이 **포기했던** 갈래가 열렸다 — `먹을만큼만 → 먹을 만큼만`은 `하늘만큼`과 문자열이 겹쳐
1층에서는 불가능했지만, `만큼/NNB`와 `만큼/JKB`는 다른 태그다.

재현율 0.849 → 0.879, 정밀도는 1.000 그대로.

2층의 근거는 이렇다. 사전에 없는 표기는 억지로 잘게 쪼개진다.

```
"어의없다" →  어/NNG + 의/JKG + 없/VA + 다/EF     ← 4조각
"어이없다" →  어이없/VA + 다/EF                    ← 2조각
```

3층의 근거는 이렇다. `수`가 `NNB`(의존명사)로 태깅되면 앞말과 띄어야 한다는 것이 확정된다.
1층에서 받침과 뒤따르는 말로 힘겹게 근사하던 판정이, 품사를 알면 그냥 풀린다.

**garu-ko는 2·3층의 재료를 공급할 뿐이고, 1층과 판정·통합은 전부 이 저장소의 코드다.**
이것이 `@gochim/core`가 npm에 나갈 가치가 있는 이유이기도 하다 — 남의 라이브러리를 감싸기만 한 게 아니다.

## 맥락 2 — 스타와 실사용 지표는 서로 다른 곳에서 나온다

- 라이브러리는 스타를 받는다. 제품은 사용자를 받는다.
- 한국 특화 서비스는 글로벌 저장소 대비 스타가 10~20배 불리하다. **예외는 "한국어를 다루는 라이브러리"뿐이다.**

## 결정 2 — 저장소를 둘로 나눈다 (Excalidraw 패턴)

| | 무엇 | 대상 |
| --- | --- | --- |
| `@gochim/core` | 순수 엔진. DOM도 크롬 API도 모른다 | npm · 다른 개발자 · 스타 |
| `gochim-extension` | 확장 UI, 밑줄 오버레이, 무시 사전 | 사용자 · 실사용 지표 |

지금은 하나의 npm 워크스페이스(`packages/*`, `apps/*`)로 두고, 배포 시점에 분리한다.
**경계는 처음부터 지킨다** — `@gochim/core`는 `document`, `chrome`, `window`를 참조하지 않는다.
순수 함수 `check(text, options) → Diagnostic[]` 하나가 전부다.

## 결과

- 코어를 Node에서 그대로 테스트할 수 있다(브라우저 없이 252개 테스트가 0.5초에 돈다).
- 데모, 확장, CLI, 에디터 플러그인이 전부 같은 엔진을 쓴다.
- 확장이 스토어 심사에 막혀도(만 18세 미성년자 이슈) 코어와 웹 데모는 독립적으로 배포된다.
