# 0004 — 골든 테스트셋을 규칙보다 먼저 만든다

- 상태: 확정
- 날짜: 2026-08-19
- 관련: [0002](0002-precision-first.md)

## 맥락

교정기 개발에서 가장 흔한 실패는 이렇게 시작한다.

> 규칙을 하나 추가한다 → 예시 문장에서 잘 돈다 → 다음 규칙을 추가한다 →
> 어느 순간 정확도가 떨어졌는데 **언제부터 떨어졌는지 알 수 없다.**

측정 기준이 없으면 "좋아졌다"는 감각일 뿐이다.
특히 정밀도는 **눈에 안 띄게** 나빠진다. 규칙 하나를 넓혔을 때 새로 생긴 오탐은
내가 시험해 본 문장이 아니라 남의 문장에서 터진다.

## 결정

**규칙을 한 줄 쓰기 전에 골든 테스트셋부터 만든다.** 데이터셋이 정확도의 유일한 기준이다.

데이터셋은 세 부분으로 구성한다.

| 부분 | 무엇 | 왜 |
| --- | --- | --- |
| `cases` | 오류 문장 ↔ 정답 문장 쌍 + 오류 구간 | 재현율 측정 |
| `negatives` | **순진한 규칙이 오탐할 정상 문장** | 정밀도 측정 |
| 정답 문장 | `cases[].right` 전체 | 공짜로 얻는 정밀도 표본 |

`negatives`가 이 데이터셋의 진짜 가치다. 오류 문장 100개를 모으는 건 쉽지만,
`실수 없이`, `말뿐이고`, `하늘만큼 땅만큼`, `부재중 전화`, `일리가 있다`, `날것으로`처럼
**규칙이 걸려 넘어질 문장**을 모으는 건 어렵다. 그리고 그게 정밀도를 지킨다.

## 만든 방법

문항 하나하나가 어문 규범 판단이라, 한 번 쓰고 넘어가면 틀린 데이터로 틀린 규칙을 만들게 된다.
그래서 **카테고리별로 생성 → 규범 검증 → 오탐 감사**의 3단 파이프라인을 돌렸다.

1. **생성** — 카테고리(되/돼, 안/않, 어휘, 의존명사 띄어쓰기, 조사·어미, 이/히)별로 독립 작성
2. **규범 검증** — "통과시키지 말고 틀린 것을 찾아라"는 지시로 재검토.
   규범상 논쟁 여지가 있으면 `cases`에서 제거하고 사유를 남긴다
3. **오탐 감사** — "이 항목을 규칙으로 만들면 어떤 정상 문장이 오탐되는가"를 전담해서 묻고,
   **찾아낸 오탐 유발 문장을 `negatives`에 추가**한다

3단계의 산출물이 실제로 규칙 설계를 바꿨다. 예를 들면,

- `수` 규칙 → `실수 없이`, `별수 없다` 때문에 ㄹ받침 명사 예외 목록이 필요하다
- `리` 규칙 → `일리가 있다`가 `일 리가 있다`가 되면 **뜻이 정반대로 뒤집힌다**
- `중` 규칙 → 블랙리스트로는 못 막는다(`도중·와중·수중·집중·열중`). 화이트리스트여야 한다
- `-을 만큼` → `하늘만큼`, `가을만큼`과 문자열이 겹쳐 1층에서는 아예 불가능

## 자동 검증 — 사람 판단에 기대지 않는 부분

데이터에는 코드로 검사 가능한 불변식을 하나 심어 두었다.

> `spans`를 순서대로 `wrongText → rightText`로 치환하면
> `wrong`이 `right`와 **문자 단위로 정확히 일치해야 한다.**

`scripts/build-golden.mjs`가 이 불변식을 강제하고, 깨진 항목은 조용히 고치지 않고 **떨어뜨린 뒤 사유를 출력**한다.
"오류 구간이 대충 맞는" 데이터는 재현율을 부풀리기 때문이다.

## 결과 (2026-08-19 실측)

| | |
| --- | --- |
| 오류 문장 | 132개 (오류 구간 132개) |
| 정상 문장 | 297개 = 정답 문장 132 + **함정 165** |
| 정밀도 | **1.000** — 정상 문장 297개에서 오탐 0건 |
| 재현율 | 0.849 |

만드는 과정에서 **오탐 감사가 실제로 규칙을 다섯 번 되돌렸다.** 처음 구현한 규칙들은 함정 문장에서
14건의 오탐을 냈고(정밀도 0.81), 그 14건을 하나씩 좁혀 1.000이 되었다. 좁힌 내용은 전부
각 규칙의 `counterExamples`로 남아 회귀 테스트가 되었다.

불변식 검증에서 1건이 떨어졌다 — 검증 단계가 오류 문장을 고치다가 `wrong`과 `right`를 같게 만든 항목이다.
사람이 눈으로 봤으면 놓쳤을 종류의 실수다.

- `npm run golden:report`가 분류별 검출률, 오탐 목록, **아직 못 잡는 오류 목록**을 출력한다.
  다음에 만들 규칙은 이 목록에서 고른다.
- 정밀도 0.98 미만이면 테스트가 깨진다. 규칙을 넓히다 오탐이 생기면 **그 커밋에서** 잡힌다.
- 재현율에는 합격선을 두지 않는다. 대신 0.3 밑으로 떨어지면 무언가 망가진 것으로 본다.
