# 0001 — 형태소 분석기로 garu-ko를 쓰고 0.9.14에 고정한다

- 상태: 확정
- 날짜: 2026-08-18
- 관련: [0002](0002-precision-first.md), [0003](0003-three-layers-and-repo-split.md)

## 맥락

고침은 **완전 온디바이스** 교정기다. 텍스트를 서버로 보내지 않는다는 것이 제품의 전제이자 유일한 차별점이다.
그런데 크롬 확장 MV3는 원격 코드 실행을 금지한다. 형태소 분석기와 그 모델을 **전량 번들**해야 한다는 뜻이다.

처음 계획은 Kiwi였다. 정확도는 가장 높지만 모델이 **34MB**다.
34MB짜리 확장은 설치 화면에서 사용자를 잃는다. 온디바이스라는 장점이 설치 장벽으로 되돌아온다.

## 결정

`garu-ko`(MIT)를 쓴다. 버전은 캐럿 없이 **정확히 `0.9.14`** 로 고정한다.

## 근거

2026-08-18에 실제 크롬에서 직접 측정했다(`tools/probe/`).

| 항목 | 실측값 |
| --- | --- |
| 초기화 | 107 ms |
| 문장당 추론 | 0.1 ~ 0.6 ms (첫 문장만 9.4 ms 워밍업) |
| WASM | 403 KB |
| 모델 | 1,217 KB |
| 합계 | **약 1.6 MB** |

Kiwi 대비 **21분의 1**이고, MVP 게이트로 잡은 "3MB gzip 미만"을 여유 있게 통과한다.

### 왜 최신 버전이 아니라 0.9.14인가

`0.9.15`(2026-08-18 배포)는 **플래그 없는 크롬에서 로드 자체가 실패한다.**

```
CompileError: WebAssembly.instantiateStreaming():
  Invalid import kind 127, enable with --wasm-compact-imports
```

`wasm-compact-imports` 제안을 켠 채 빌드된 WASM이라 stock 크롬과 Node 24 양쪽에서 컴파일이 거부된다.
Node에서는 `unknown import kind 0x7f`로만 나와 원인을 알 수 없었고, **크롬 콘솔이 정확한 진단을 줬다.**

그래서 두 가지를 규칙으로 굳힌다.

1. `npm update`나 의존성 자동 갱신을 걸지 않는다. 캐럿(`^`)도 쓰지 않는다.
2. garu-ko를 올리기 전에는 반드시 `npm run probe:sync` 후 **브라우저 실측을 먼저 통과**시킨다.
   `tools/probe/`가 그 자리다. 상류가 0.9.16+에서 되돌릴 수 있으므로 주기적 재확인에는 가치가 있다.

## 결과

- 번들 예산에 여유가 생겨, 확장에 규칙 사전과 무시 사전을 넉넉히 실을 수 있다.
- 대신 **판정 로직을 직접 만들어야 한다.** garu-ko는 형태소 분석기지 맞춤법 검사기가 아니다 → [0003](0003-three-layers-and-repo-split.md)
- Phase 0은 형태소 분석 없이 1층(순수 문자열 규칙)만으로 굴러간다. garu-ko는 Phase 1에 붙는다.
