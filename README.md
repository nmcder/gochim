# 고침 · Gochim

**브라우저 안에서만 도는 한국어 맞춤법·띄어쓰기 교정기**

입력한 글이 기기 밖으로 나가지 않습니다. 서버도, API 키도, 네트워크 요청도 없습니다.

</div>

![고침 웹 데모](docs/images/demo.png)

## 왜 만들었나

한국어 교정 도구는 대부분 **글을 서버로 보낸다.** 블로그 글이면 상관없지만
자기소개서, 진단서, 아직 공개하지 않은 원고라면 이야기가 다르다.

고침은 `check(text) → Diagnostic[]` 하나짜리 순수 함수다. 부작용도, 통신도, 전역 상태도 없다.
엔진 전체가 **gzip 128 kB**이고 런타임 의존성이 0개다. (절반 이상이 "왜 틀렸는지" 설명 텍스트다)

## 측정값

골든 테스트셋(오류 문장 227개 · **정상 문장 553개**)에 대한 실측입니다.
정상 문장 553개 중 326개는 "순진한 규칙이 오탐할 문장"만 골라 따로 만든 함정입니다.

| | |
| --- | --- |
| **정밀도** | **1.000** (오탐 0건 / 정상 문장 553개) — 형태소 층을 켜도 1.000 |
| 재현율 | 0.957 (1층만) → **0.961** (형태소 층 포함) |
| 규칙 | 문자열 232개 + 형태소 9개. 예시 929개, 반례 1,388개가 관문으로 강제됨 |
| 테스트 | 3,573개 |
| 검사 속도 | 1층 **4,000자 2.66ms** (p95 3.13ms) · 1,000자당 0.66ms (`npm run bench`) |
| 형태소 층 초기화 | 70~101ms, 한 번만 (크롬 실측) |
| 번들 | 코어 minified 588 kB · **gzip 128 kB**, 런타임 의존성 0개 (`npm run size`) |

저장소 안의 한국어 산문 47,000여 자(README·ADR·규칙 파일 주석·테스트)에도 규칙을 돌려 봅니다.
지적이 나오는 자리는 일부러 넣어 둔 오류 예시뿐입니다.

**위 재현율은 새 규칙을 넣어도 움직이지 않습니다.** 표본에 그 오류 갈래가 없기 때문입니다.
숫자를 살리려고 표본에 넣지 않았습니다 — 규칙을 지은 손으로 표본까지 지으면
그 순간 성적표가 거짓말을 시작합니다.

### 처음 보는 글에서의 성적

일기 한 편으로 규칙을 다듬으면 그 글에서는 1.000이 나온다. 그게 실력이 아니라는 것을
확인하려고 **갈래가 다른 글**을 따로 만들었다 — 메신저·이메일·자기소개서·댓글·후기·
리포트·일기·레시피·사과문·손편지·소식지·SNS·질답, 그리고 사용자가 확장에 직접 넣어 본 글 두 편.
정답은 쓴 쪽과 다른 눈이 반증 검증했다.

| | |
| --- | --- |
| 표본 | 15편 9,613자 · 오류 **463건** |
| 재현율 | 0.786 (1층만) → **0.955** (형태소 층 포함) · 과교정 **0건** |
| 모두 고친 뒤 정답과 **글자까지 같은 글** | **4/15** |

이 숫자는 한 번 **떨어진 적이 있다.** 표본이 7편일 때 0.901이었는데 13편으로 늘리자
0.654가 됐다. 규칙이 나빠져서가 아니라 그 0.901이 7편에 맞춰 다듬어 얻은 값이었기
때문이다. 처음 보는 6편에서는 0.14~0.29였다. 표본을 되돌려 숫자를 살리는 대신
하한선을 내리고 이유를 [guard.mjs](scripts/guard.mjs)에 적어 두었다.

갈래별로는 열다섯 편 가운데 열한 편이 0.9를 넘고, 가장 낮은 사과문이 0.867이다.
`npm run corpus:report -- --morph` 로 갈래별·분류별 성적과 못 잡은 목록을 본다.

`npm run guard` 는 넘으면 안 되는 선을 한 번에 확인한다 — 정상 문장 829개 오탐 0
(1층과 형태소 층 각각), 규칙 241개의 예시 자가검증, 정답 불변식, 재현율 하한선.
어기면 종료 코드 1이다. 확장이 형태소 분석기를 기본값으로 켜 두므로 두 층을 다 잰다.

### 실문(實文) 성적표

유형별로 문장을 하나씩 만든 골든셋은 **실제 글에서 어떤 오류가 얼마나 자주 나오는지**를
반영하지 않습니다. 그래서 사람이 쓴 글 한 편을 전수 조사해 따로 잽니다.

| | |
| --- | --- |
| 표본 | 일기 1편 1,455자 · 오류 **66건** (3단계 검증한 정답) |
| 재현율 | **0.985** · 과교정 0건 |
| 모두 고친 뒤 정답과 **글자까지 같은 문단** | **7/7** |

마지막 줄이 진짜 성적입니다. 구간이 겹치기만 해도 잡은 것으로 세면 점수가 후해집니다 —
`몇분뒤에`를 `몇 분뒤에`까지만 고쳐도 재현율에는 잡힌 것으로 들어가지만
사용자 눈에는 여전히 틀린 글이 남습니다. 그래서 '모두 고치기'를 누른 것과 똑같이
전부 적용한 뒤 정답과 통째로 견줍니다.

이 표본을 처음 넣었을 때는 **0.127**이었습니다. 골든셋 재현율이 0.94인데도 그랬습니다.
오류 63건 중 56건이 띄어쓰기였는데, 골든셋 문장에는 늘 조사가 붙어 있어서
`~하는 것 같다`처럼 **조사 없는 의존명사**를 통째로 놓치고 있었기 때문입니다.
`npm run prose:report` 로 재현할 수 있습니다.

```bash
npm run golden:report   # 분류별 검출률 · 오탐 목록 · 아직 못 잡는 오류 목록
```

## 지금 되는 것

```ts
import { check, fix } from '@gochim/core'

fix('몇일 뒤에 할수있어.')
// '며칠 뒤에 할 수 있어.'
```

- **맞춤법** — `됬어→됐어`, `어의없다→어이없다`, `않되요→안 돼요`, 사이시옷, `-이/-히`
- **외래어** — `컨텐츠→콘텐츠`, `악세사리→액세서리`, `케잌을→케이크를`(조사까지 함께 고침)
- **높임** — `커피 나오셨습니다→나왔습니다`, `품절이십니다→품절입니다`, `저희 나라→우리나라`
- **겹말** — `다시 재발→재발`, `역전앞→역전`. 틀린 게 아니라 문체라 경고로만 알립니다
- **띄어쓰기** — 의존명사 `수·것·거·뿐·리·줄·채·바·김·때문·적·중` 등, 조사·어미 붙여쓰기(`너 뿐만→너뿐만`, `할 지→할지`)
- **어미·서술격** — `할께요→할게요`, `뭐에요→뭐예요`, `했슴→했음`
- **받침으로 푸는 규칙** — `경쟁율→경쟁률`(두음법칙), `년도별→연도별`, `책예요→책이에요`
- 각 진단은 **왜 틀렸는지**와 **한글 맞춤법 조항**을 함께 준다 → [규칙 목록](docs/rules.md)
- URL·이메일·코드·HTML 태그·파일 경로·짧은 인용은 건드리지 않는다
- 형태소 층을 켜면 품사로 판정한다 — `네 말 대로`는 붙이고 `들은 대로`는 띄운다
- 어미 표기도 품사로 푼다 — `좋구요→좋고요`, `먹드라→먹더라`, `처음이여서→처음이어서`, `입을려고→입으려고`.
  `친구요·도구요`처럼 `구`가 명사의 끝 음절인 자리는 같은 조건 하나로 함께 빠진다

## 확장은 이렇게 쓴다

붙여넣고 검사 단추를 누르는 도구가 아니다. 평소 쓰던 자리에서 쓰던 대로 쓰면 된다.
어느 사이트든 `<textarea>`, `<input>`, `contenteditable`이면 붙는다.

| 하는 일 | 방법 |
| --- | --- |
| 오류 알기 | 타이핑을 멈추면 그 자리에 밑줄이 그어지고 고침 카드가 뜬다 |
| 하나 고치기 | `Alt + Enter` (설정에서 `Tab`·`Enter`로 바꿀 수 있다) |
| 카드 닫기 | `Esc` |
| **다 고치기** | 카드의 `모두 고치기 N` 또는 `Alt + Shift + F` |
| 되돌리기 | `Ctrl + Z` — 모두 고치기도 입력칸에서는 **한 번**에 전부 돌아간다 |
| 이 지적 그만 보기 | 카드의 `무시` — IndexedDB에 남아 다음부터 그 표기는 지나친다 |

자동 고침을 켜면 확신도가 높은 오류는 묻지 않고 고친다. 다만 **커서가 지나간 낱말만**
손댄다 — 지금 치고 있는 글자가 밑에서 바뀌면 입력이 망가지기 때문이다.
그래서 이미 써 둔 글은 자동 고침이 손대지 않고, 그 자리를 `모두 고치기`가 맡는다.

크롬이 그리는 빨간 물결과 밑줄이 겹쳐 두 줄로 보이지 않도록, 붙어 있는 동안만
입력칸의 `spellcheck` 속성을 끄고 손을 뗄 때 원래대로 돌려놓는다.
[호스트 DOM을 건드리지 않는다는 원칙](docs/decisions/0005-extension-never-touches-host-dom.md)의
유일한 예외이고, 설정에서 끌 수 있다.

## 지금 안 되는 것 (의도적으로)

문맥 없이는 판정이 불가능한 것들이다. 억지로 잡으면 맞는 문장에 밑줄이 그어진다.

| 포기한 것 | 이유 |
| --- | --- |
| `-ㄴ 지` / `-ㄴ지` | `먹은 지 한 달`과 `범인인지 한 달`이 문자열로 같다 |
| `안되다` / `안 되다` | 둘 다 표준어이고 뜻이 다르다 |
| `한번` / `한 번` | 부사냐 횟수냐에 따라 갈린다 |
| `반듯이` / `반드시` | 자세냐 확실함이냐는 문맥이 정한다 |
| `지양` / `지향` | 회피냐 추구냐는 문맥 의미가 정한다 |

품사를 알아야 풀리는 문제라, **형태소 분석 층(Phase 1)** 으로 미뤘다.
자세한 근거는 [ADR 0002 — 정밀도 우선](docs/decisions/0002-precision-first.md).

### 포기했다가 되찾은 것

포기 목록은 영구 선언이 아니다. **문맥 신호가 분명한 좁은 자리**만 떼어 내면
정밀도를 깨지 않고도 잡을 수 있는 것이 있었다.

| 되찾은 것 | 어떻게 |
| --- | --- |
| `-을 만큼` | 관형사형 어미가 될 수 있는 음절만 화이트리스트로 받는다. `하늘만큼·서울만큼`은 그 목록에 없다 |
| `하던지` / `하든지` | 선택의 나열(`먹든지 말든지`)만 잡는다. 회상의 `-던지`는 나열되지 않는다 |
| `재고` / `제고` | `경쟁력 재고에`처럼 앞에 높임의 대상이 오는 자리만 본다. `창고에 재고가`는 건드리지 않는다 |

`지양/지향`은 아직 남아 있다. 앞뒤 어디에도 방향을 알려 주는 말이 없는 문장이 흔하다.

문법 검사, 문체 개선, AI 재작성은 **범위 밖**이다.

## 구조

```
packages/core/     @gochim/core  — 엔진. DOM도 크롬 API도 WASM도 모른다
packages/morph/    @gochim/morph — 형태소 분석기 어댑터 (garu-ko)
packages/store/    @gochim/store — 무시 사전 (IndexedDB)
apps/demo/         웹 데모 (Vite)
apps/extension/    크롬 확장 (MV3) — 네트워크 권한 없음
data/golden/       골든 테스트셋 — 정확도 판정의 유일한 기준
tools/probe/       garu-ko 브라우저 실측 하네스
docs/decisions/    설계 기록(ADR)
```

판정은 3층으로 쌓는다.

| 층 | 방식 | 상태 |
| --- | --- | --- |
| 1층 · 규칙 사전 | 문자열 패턴 + 받침 계산 | ✅ |
| 3층 · 품사 기반 띄어쓰기·어미 표기 | 형태소 태그(NNB·J*·EC·VCP) | ✅ |
| 2층 · 형태소 이상 탐지 | 점수 기반 오타 탐지 | [기각](docs/decisions/0006-rejected-score-based-typo-detection.md) |

**코어는 형태소 분석기를 모른다.** `check(text, { analyzer })`로 주입받을 뿐이다.
그래서 코어만 쓰면 128 kB로 끝나고, 정확도가 더 필요할 때만 1.66 MB를 얹는다.

## 개발

```bash
npm install
npm run dev                     # 웹 데모
npm test                        # 테스트
npm run typecheck               # 코어·데모·확장 전부
npm run golden:report           # 골든 성적표 (1층만)
npm run golden:report -- --morph  # 형태소 층까지 켜고
npm run corpus:report           # 갈래가 다른 실문 7편 성적표
npm run guard                   # 넘으면 안 되는 선을 한 번에 확인
npm run build:extension         # 크롬 확장 → apps/extension/dist
npm run bench                   # 성능 측정 (--morph로 형태소 층 포함)
npm run size                    # 번들 크기 실측 — README의 숫자는 여기서 나온 값이다
npm run pack:extension          # 배포용 zip → apps/extension/release/
npm run probe:sync              # garu-ko 실측 하네스 에셋 동기화
```

## 배포

세 패키지 모두 `npm publish --dry-run`을 통과합니다 (core 215 kB, morph 6.2 kB, store 4.8 kB —
`npm pack --dry-run`으로 다시 잴 수 있습니다).

`prepublishOnly`가 [check-publish.mjs](scripts/check-publish.mjs)를 부릅니다. `dist`는
`.gitignore` 대상이라 새 클론에서 그냥 publish 하면 **빈 패키지가 나가는데**, 한 번 나간 판은
다시 못 씁니다. 그래서 파일이 다 있는지만 보지 않고 **받는 쪽 흉내를 냅니다** — CommonJS에서
불러도 닿는가, 최상위 `await`가 섞이지 않았는가, 소스맵이 안 나가는 파일을 가리키지 않는가,
세 패키지 판이 어긋나지 않았는가, 코드에 적어 둔 `VERSION`이 `package.json`과 같은가.
하나라도 어기면 publish가 시작되지 않습니다.

```bash
npm run pack:extension   # apps/extension/release/gochim-extension-v0.2.0.zip (1.45MB)
```

태그를 밀면 GitHub Actions가 검증·빌드·zip을 만들어 릴리스 초안에 붙입니다.
크롬 웹 스토어 등록은 개발자 약관상 미성년자라 보류하고, 받는 사람은 zip을 풀어
`chrome://extensions → 압축해제된 확장 프로그램을 로드`로 설치합니다.
